# 完整客户端请求的 429 修复与实连记录

日期：2026-11-16。原始请求、账号映射和工具日志保存在仓库外受限目录；本文件不包含凭据、用户 SOUL 或私有提示原文。

## 已证实的问题

Google 对部分完整客户端请求直接返回 `429 RESOURCE_EXHAUSTED`。同一固定账号、同一模型能完成 dsh 与媒体请求，不能将这些失败简单解释成所有账号额度耗尽。

使用真实请求进行逐段诊断后，确认部分固定客户端框架文本与失败相关。诊断中的删段、拆段等实验只用于定位，没有作为完整客户端验收。产品转换只处理已核实来源和精确指纹的官方框架：

- Pi 1.5.2：官方文档主题索引中的 `non-LLM models` 展开为同义表述，文档路径、工具、角色和所有用户内容保留。原文 → 修复 → 恢复原文的对照分别失败、成功、失败。
- Claude Code 2.1.322：SDK 普通与 compact 模板的固定安全段落中，将 DoS、C2 展开为全称。允许范围、拒绝规则、授权要求逐项保留，不删除安全约束，不改 Auto 审批配置或结论。
- Hermes 0.23.1：对已验证的默认风格开头、官方文档说明、任务完成段落和模型执行标题作等义转换，规范运行环境外层标题。自定义 SOUL、项目内容、环境值、技能路径、禁止编造要求、工具及执行权限保留。
- Codex CLI 0.167.2：补充从 Codex Desktop 启动时的实际 UA / originator 组合识别，继续要求原有完整 developer 模板指纹，复用已有身份转换，不凭请求头单独清理文本。

这些证据证明上述请求转换有效，**不证明 Google 内部采用了哪种过滤、容量或风控机制，也不意味着所有 429 都能通过文本转换解决**。真实额度、限流与服务故障仍原样分类返回，账号粘性、冷却、轮询和额度保护保持不变。

## 保留的失败与边界

- Claude 最初只处理 compact 模板；Sonnet 使用普通 SDK 模板，复测仍 429。补齐精确普通模板后，上表 Sonnet 完整闭环才通过。
- Linux Hermes 用例 `1794825580286-hermes-a31f75e1` 工具与 SSE 正常，但模型写文件时漏了末尾换行。字节验收失败，没有改网关为工具内容补换行。后续同类原任务复测通过；该失败不删除。
- 私有验收器并发启动 Pi/Claude 时曾使用相同毫秒目录，结果互相污染。该批全部作废，停止自有测试进程、恢复配置，并改为独立目录后重测；不计为产品故障或通过证据。
- Codex 自带 Responses `web_search` 声明原先被旧入口明确拒绝。新适配使用已捕获的官方 `search_web` 和真实目录中的搜索辅助接口；客户端工具仍由客户端执行。Google 内置搜索与函数混合的直接探测返回 400，未将该不可用组合装入产品。
- Gemini Task 多模态及首次原生弹窗与 API 初始化状态的对应关系仍按用户决定暂缓，不在本次 429 修复中扩大承诺。
