# Hermes 2.0.5 真实环境验收

2026-11-15，修复来源是服务器 Hermes `0.23.1+4394.gc9b20d7` 保存的完整失败请求，而非简化的聊天样本。模型保持 `gemini-3.8-flash-high`，请求中全部 19 个客户端工具、SOUL、自定义规则、技能目录和记忆均保留。请求原文及完整运行记录保存在仓库外的权限受限目录。

## 根因与修复边界

旧代码固定要求第二段为 Hermes 官方文档说明，第三段为 `# Finishing the job`。默认身份后追加用户规则会使这些段落后移，导致模板识别失败。修复定位精确文档段落，并验证相邻框架结构；身份清理仍要求默认首段的 SHA-256 完全匹配。实际原始请求的结构核验确认：仅默认身份句发生变化，用户规则、消息及工具保持原样。

之前的真实对照中，原始完整请求返回 429；只删除默认身份句即返回 200，恢复后再次 429。Google 只给出通用 `RESOURCE_EXHAUSTED`，内部拒绝原因未公开。不能据此断言账号封禁或余额耗尽。

错误适配只针对 Google 明确返回的结构化状态，输出 `resource_exhausted`，保留内部 `direct_upstream_error` 供诊断；不修改账号轮询、粘性或额度判断，不制造重试成功承诺。

## 实际验证方法

- 将候选包安装到本机原安装位置和服务器原安装位置，继续使用原数据目录、账号池和端口。服务器从 `https://anti.dreambook.chat` 公网入口验证，本机从 `http://127.0.0.1:9897` 验证。
- 两份原始失败请求分别通过 Messages 和 Responses 发出；每份验证 JSON 与 SSE，共两端八项。唯一主动变化的请求字段是 `stream`。没有删除系统提示、工具或改选模型。
- 每项必须收到实际非空模型回答、有效用量和正确终止事件；出现错误事件、截断、工具调用未完成或只有 HTTP 200 均不能判为成功。
- 实际启动服务器原安装 Hermes，无模型、协议或配置覆盖参数：完成“你好”对话，以及读取仅存在于服务器文件中的随机中文内容并准确回传。读取由 Hermes 执行，网关不执行工具。
- 另用保留全部原始规则的自定义身份边界请求获取真实 Google 429：验证 Messages JSON 错误，以及实际 Hermes OpenAI SDK 收到的 Responses SSE 错误。调用其原安装版本的流错误处理器和分类器，确认 `rate_limit`、`retryable=true`。

候选包通过之后才将版本更新为 2.0.5。发布包再次部署后，重新运行两端八项完整请求验收。最终脱敏结果、包摘要和配置完整性检查记录在 [验收摘要](hermes-2.0.5-live-summary.json)。

最终 2.0.5 的两端八项全部通过。已有 Hermes 会话在网关升级重启后，再次读取更新后的随机中文内容并准确回传；该轮只有一次 `read_file`，没有搜索或写入工具。原始请求验证、真实客户端验证和错误验证分别记录，不合并成“所有模型／所有工具通过”。

服务器原 API key 与面板密码分别验证仍可使用，错误 key 与匿名面板访问仍返回 401；本地保持原有 loopback 访问方式。账号池本地 4 个、服务器 10 个，身份及刷新凭据未变。Hermes 测试中自行持久化了一项长工具提示 UI 标志，退出后恢复了测试前的配置原文；最终配置、SOUL、`.env` 均与测试前字节一致。

## 保留的未通过样本

首次扩展文件读取使用英文随机标识。Hermes 实际读到了该行，但模型随后继续搜索其他文件，没有及时给出最终答案；该次任务被中止，未算作成功。用户 SOUL 要求纯中文输出，后续使用随机中文内容完成了独立读取闭环。这只能证明后者完整通过，不能据此断言前者偏离任务的内部原因，也不代表所有工具与模型行为都已验证。

## 后续复验

使用真实客户端保存的完整请求体文件；不要把用户 SOUL、原始请求或密钥放入仓库。脚本读取现有服务配置中的 API key，不写入客户端配置；未设置 key 的原有本机服务只允许 loopback 验证。

```sh
node scripts/verify-live-request.js \
  --base-url https://your-existing-gateway.example \
  --service-config /absolute/private/antigravity-gateway-service.json \
  --body /absolute/private/original-responses-body.json \
  --protocol responses \
  --out /absolute/private/new-live-run
```

Messages 使用 `--protocol messages` 和对应的原始请求体。默认依次执行 JSON 与 SSE，可用 `--modes json` 或 `--modes sse` 选择单项。输出目录必须不存在，防止覆盖旧证据。脚本不启动客户端、不执行返回工具，也不提供模拟上游；文件工具闭环必须另用真实客户端执行并核验工具回执及最终答案。
