# Gemini App / Robin Provider（开发中）

Robin 是同一网关内部的独立上游，不是第二套后台。客户端仍使用原有端口及 Messages、Chat Completions、Responses 接口；明确请求 `gemini-4-argon` 才会进入 Robin 账号池。提示词内容不参与 Provider 选择。

## 授权与部署

本文的原生任务、MCP、附件、设备注册与额度内容专指 Robin OAuth 通道。1.6.0 新增的 Windows 网页会话通道不使用这些协议，授权和能力边界见 [Windows 原生通道](windows-native.md)。

所有系统在网关交互终端输入 `add-gemini`，均保持 1.5.1 的独立 Google OAuth 流程。服务器没有浏览器时，可以在自己的电脑上打开链接，再将完整回调地址粘贴到仍在等待授权的网关终端。Windows 新增的 `add-gemini-win` 使用独立浏览器会话和 `gemini-win-accounts/`，不覆盖这里的 OAuth 凭据；网页会话不是 OAuth 回调，不能通过粘贴旧回调 URL 转换。

凭据永久保存在配置目录的 `robin-accounts/`，与 Antigravity 的 `accounts/` 分开。Robin 目录与每次原子替换后的凭据文件分别使用 `0700`、`0600` 权限；不应提交到仓库。独立 refresh token 和 Robin server token 由网关刷新，正常请求不依赖 Gemini App 或 agy 子进程。

Robin 账号池只接收 Robin / Gemini App 凭据，Antigravity 账号池拒绝显式标记为 Robin 或 Gemini App 的凭据；误放的凭据不会被自动删除。旧版 JSON 中曾被忽略的未知类型标签仍沿用 Antigravity 行为，不因新增 Provider 被误排除。Robin 授权在准备监听器时即锁定同一次流程，拒绝重复启动；没有浏览器或打开浏览器失败仍可手动完成，异常回调 URL、错误 HTTP 方法及不匹配的 state 不会使监听器崩溃或完成授权。准备或提示回调失败时会释放监听器。

重新授权、账号身份变化或删除后重新添加，会使旧任务及旧的异步检查结果失效，不能覆盖当前账号的额度、模型能力或健康状态。普通 access/server token 轮换，以及由本账号鉴权模块保存的 OAuth refresh token 轮换，不改变正在进行的任务及软黏性；鉴权模块只认可自己当前保存的授权，磁盘上的另一份授权或旧 refresh token 不能继承旧任务。健康状态仍按请求实际使用的凭据版本归属，旧 token 的迟到成功或失败不会覆盖新 token 的健康判定。用于归属检查的本地指纹不发送给模型，也不出现在客户端协议响应中。

若原生请求明确返回 `412` 且要求接受 Gemini 服务条款，网关不会隔离账号或自动切换账号，而是保留并直接返回上游原始错误，再追加“请登录在 Gemini App 当前账号 xxxxx 并同意服务条款”的中文提示，其中 `xxxxx` 是本次实际路由账号。其他 `412` 错误不追加该提示。

现有诊断日志的大小上限和轮换规则不变；脱敏同时覆盖 OAuth 凭据与 Robin server token，包括嵌套字段、请求头名称和序列化错误文本。相关测试只使用合成凭据，不将真实凭据写入日志。

设备注册按实际 access token 合并，并使用账号级的独立取消信号及 30 秒超时。某个客户端取消等待不会中断其他客户端共用的注册；新 token 不复用旧 token 正在进行的注册。账号停用、删除或授权更换时，Provider 会取消正在准备附件的请求及设备注册，晚到的准备结果不能再启动任务。

模型能力与额度元数据查询同样纳入 Provider 的取消管理，单次最多 30 秒，调用方更短的截止时间优先。停止账号会关闭查询连接，迟到的授权或查询结果不能转成成功回复；一个客户端取消自身查询不取消其他查询。普通模型目录刷新不重新探测已隔离或仍在冷却中的账号，只保留先前确认的目录；显式“重新检测”仍可验证并恢复账号。已删除或授权已更换的账号不能通过失败查询的旧缓存重新出现在目录中。后台额度检查保留 15 秒截止时间；快照刷新采用三通道统一周期，见下文。

授权成功不等于获得 Argon 权限。网关通过原生 `GetUserStatus` 中的模型定义及可选模型 ID 确认访问能力，然后更新统一模型目录。普通 Robin 文本、图片、音频、PDF、文件和工具任务故障或没有 Argon 权限时明确报错，不降级到 Cloud Code 的其他 Gemini 模型。

视频是明确例外。Gemini App 的 Argon 视频流程由客户端本地抽帧，不是已确认的模型原生视频理解；因此请求选择 `gemini-4-argon` 且实际携带视频时，网关不再上传给 Robin，而是沿用原有多媒体判断、Cloud Code 账号池和 `ANTIGRAVITY_DEFAULT_MODEL`。模型仍自行判断附件是上下文还是生成参考，不使用提示词关键词路由。仅有文本、图片、音频、PDF 或普通文件时保持 Robin；默认模型若也映射到 Robin，则明确返回 `argon_video_fallback_unavailable`，不循环路由。

联合模型目录查询和推理请求相互独立。首次 Cloud Code 请求或暂未出现在目录中的新模型 ID 不等待 Robin 目录刷新；原有账号池继续执行自身的模型能力筛选和账号调度。Cloud Code 错误的模型目录诊断也只查询 Cloud Code / agy，并保留一分钟缓存；重新检测或删除对应账号后使诊断缓存失效。已知 Robin 模型即使账号不可用仍不进入 Cloud Code，明确的 Provider 归属冲突仍报错。该隔离不取消 `/v1/models` 及客户端配置的模型并集。

原有独立 Images 接口仍使用已实现的 Cloud Code 私有生图通道。明确指定 `gemini-4-argon`，或配置了映射到它的别名时，`/v1/images/generations`、`/v1/images/edits` 暂返回 `501 / robin_images_not_implemented`，不会代用 Cloud Code 账号和额度。没有指定模型或原有 Cloud Code 请求维持既有行为；提示词出现“Argon”不参与这一判断。这是当前 Robin Images 适配尚未接入的限制，不表示已确认原生模型不能生图，也不把拒绝错误算作图片能力实现完成。

显式 `agy` 或 `auto` 回退模式只改变 Antigravity 的传输，不使 Robin 依赖本机 CLI。模型目录分别查询两个来源，单个来源失败不会跳过另一来源；`/v1/models`、`claude-models.json` 和 `codex-models.json` 使用同一结果并集。两个来源均不可用且没有已知目录时保留真实发现错误，不凭授权猜测模型权限。已发现的 Argon 也显示在启动模型列表，单独的 CLI 版本检测失败不遮住它。Cloud Code Auto Mode 的快速模型发现仅查询自己的来源，与模型错误诊断共用一分钟缓存；请求 Argon 的 Auto Mode 保持 Robin 归属，主动联合目录刷新仍查询两类账号。

## 工具调用与会话

### macOS Robin 客户端定向适配

v1.7.0 起，网关复用已捕获的 Claude Code 2.1.285、Codex 0.159.2、Hermes 0.21.7 能力识别，在 Robin Provider 内应用双向映射。Claude 的 Read/Write/Edit/Bash、Codex 的 exec_command/write_stdin/view_image、Hermes 的 read_file/write_file/patch/terminal 使用与 Cloud Code 适配一致的可逆名称和参数转换，但在 Robin 上它们属于 `external_client` MCP 目录，不冒充 Gemini 内置工具。

- 仍使用原生 `ProcessQuery`、`list_mcp`、`execute_mcp` 和 `ExecuteRemoteTools`，不引入 Cloud Code 请求结构、签名或恢复状态。
- 不注入 agy 身份，也不添加 `toolAction` / `toolSummary` 等 Cloud Code 元数据。只移除已识别的固定客户端身份句并调整固定框架中的工具引用；用户 SOUL、项目规则、权限、真实运行信息保持不变。
- 工具目录与转换器随活动 Robin 任务固定；后续请求即使省略工具定义，结果仍按实际交付的调用 ID 回到原生调用名称及原连接。显式结果名称必须匹配客户端实际收到的名称。重复的相同未完成调用不再次交付，冲突 ID 或无法无损转换的参数终止该任务，不修改账号健康、不换号重放。
- 新任务重放历史时，仅转换结构化 assistant 工具调用。参数必须通过原 Schema 及双向还原检查；用户文字、路径、命令、引用和工具结果正文不做字符串替换。未知工具、修改后的能力声明、名称冲突、歧义模板及 Codex 自定义补丁继续原兼容路径。
- 原生工具流不能跨网关进程恢复；v1.7.1 起，允许依据下一次客户端请求自带的完整调用与结果历史建立新查询，而不重放旧工具调用。已完成对话继续使用原有按账号及会话隔离的 Robin 游标；不新增提示词或工具结果落盘。
- 本次不改变 Windows `ProcessSession` 通道、账号调度、额度、看板或视频回退。客户端识别只是本地适配选项，不是鉴权，不发送给 Google。

2026-10-20 验证：18 项新增针对性回归、全量 704 项测试均通过。经 `npm pack` 和独立前缀全局安装，未修改的实际 Claude Code 2.1.285、Codex 0.159.2、Hermes 0.21.7 均通过本机新网关连接真实 Google Argon。最终安装包的三组原生任务均返回 HTTP 200 / gRPC 0，响应模式 ID 为 `95a4c0abcba24364`，请求 surface 为 21；共 11 次实际客户端工具执行，结果文件均经独立磁盘核验。Claude 和 Hermes 各完成读→写→编辑→命令，Codex 完成命令→原始 apply_patch→命令。工具目录、原生调用、还原参数和原连接回执由保存的双向 gRPC 字节及客户端 API 报文独立比对，不以模型自述或单元测试替代。

证据目录：项目同级 `antigravity-robin-client-20261020.Vu7hRb/`，包含报告、原始请求/响应、CLI 结果、正式包和校验清单。最初账号的服务条款 412、未加认证的客户端探测和不受支持的自动探测路径均保留，不算通过样本；切换到另一已有账号后完成验证，未自动接受条款。额外中间 Claude 成功样本与最终包复验分开记录。该验证不声称 Gemini App 全部指纹一致，也没有声称未完成 Robin 工具流能够跨重启恢复。

1. `ProcessQuery` 承载任务模式初始化、消息、附件、设备上下文和回答。
2. 服务端返回独立会话与路由信息后，建立 `ExecuteRemoteTools` 通道。
3. 网关把客户端声明的工具目录交给 Argon，将上游工具调用转换为客户端原有协议。
4. 文件读写等工具由客户端执行，结果通过网关回传到原有任务通道。网关不执行模型要求的本机 shell 命令。
5. 客户端、客户端会话、Provider 和账号共同隔离上游任务。工具任务未完成时不切换账号重放，避免重复执行客户端副作用。

工具路由仅从原生 `ContinuationIdentifiersResponse`（1014/1）读取，不从回答正文、附件或普通响应 ID 搜索。流正常结束也不等于任务成功：原生结束状态明确为 Partial 时，网关返回未完成错误；已完成的回答仍按原有协议交付。

原生 MCP 工具确认使用已验证的 Janus 类型标记处理，不从卡片标题、图标或提示词推断函数名。网关把原生按钮携带的控制消息按 `ACTION_BLOCKS` 来源和确认响应标记续接到同一个会话，仅推动上游发出真正的工具请求；实际函数名及参数仍取自 `ExecuteRemoteTools`，交给客户端现有的校验、审批和执行机制。客户端拒绝时回传真实工具失败，不替客户端同意执行。文件夹、网络、电脑控制等其他原生授权确认不自动处理，返回 `robin_confirmation_required`。

确认会开启新的查询，但不会提前关闭仍在使用的工具通道；每个工具结果回传到实际发来调用的那条连接，不能换到最新连接重放。连接确认、工具消息和回答中提供的原生会话 ID 均校验归属，不交付其他会话的消息。此路径已通过原生确认→写入→读回→最终回答的真实往返，以及 Hermes CLI 的确认任务测试。重复确认、会话 ID 冲突、旧连接鉴权归属、取消与结果源连接结束均有回归测试。

原生流正常结束却仍明确标记 `Running` 时，只有取得可信 `conversationId` / `requestId` 才启用有限读取恢复。网关保留原工具通道，通过原生 `GetConversationTurn` 读取同一任务，并请求消息树以保留原生确认卡片；不重发用户提示词或客户端工具。快照中的会话、请求和任务状态归属均需匹配，只交付原生选定的响应和实际模式，旧查询世代的晚到快照不参与交付。主动读取预算与已有 `ANTIGRAVITY_GATEWAY_TIMEOUT_MS` 对齐，默认约 5 分钟、最多 150 次，客户端更短的截止时间仍立即生效；每个 RPC 最多 10 秒。客户端工具或审批结果尚未返回时暂停读取，用户取消、账号停用或删除时停止。读取接口的临时故障与限速仅重试读取，不冒充模型额度耗尽；正常完成的请求不增加读取调用。超过上限、缺少可靠标识或原生快照无效时仍明确报错，不将流结束当成成功。真实故障注入（丢弃后续任务帧）已验证此路径完成确认、单次写入、读回和最终回答；它不代表所有网络断开都能恢复。复杂约束任务曾暴露旧两分钟窗口会在正确结果稍后完成前误报超时；调整后的开发 Provider 已实际在约 175 秒交付正确 JSON，最优结果经本地穷举 7,560 条合规路线核对。该轮只提交一次原生任务，完成前读取同一任务 48 次，没有重发提示词；这个复杂任务测试不替代全部客户端协议的实机覆盖。

新会话选择与现有会话软黏性由 Robin 账号池维护，但选号策略与 Antigravity、Windows 通道共用 `src/account-scheduling.js`。统一通过 `ANTIGRAVITY_AFFINITY_TTL_SECONDS` 设置固定窗口，默认 5 小时，成功请求不续期；旧 `ANTIGRAVITY_ROBIN_AFFINITY_TTL_SECONDS` 仅在统一变量未设置时作为三条通道共用的兼容别名。`ANTIGRAVITY_ROBIN_TURN_TTL_SECONDS` 默认 30 分钟，约束等待工具结果的任务生命周期，两者不是同一个期限。进程重启可恢复软黏性，但不能恢复内存中的双向工具流。

v1.7.1 起，原流失效、超时或重启之后，下一次客户端请求若包含对应的 assistant 工具调用及工具结果，直接以客户端提供的完整上下文建立新查询，不强制恢复原生旧任务。历史结果仅作为历史转发，不写入新建工具通道，也不要求客户端重做工具。没有新客户端请求就不新增查询；正在处理的请求若遇到上游故障，仍正常返回错误，由 agent 决定是否重试。明确会话下缺少调用历史的孤立回执返回 `400/robin_tool_history_missing`。网关不生成“继续任务”提示、不执行工具、不替 agent 决定任务。

已完成的原生对话会保存 `conversationId`、`parentRequestId`、`parentResponseId` 三个传输游标，下一轮通过原生 `RequestIdentifiers` 续接。游标按客户端、会话和账号隔离，以哈希键、`0600` 文件保存，默认 5 小时过期、每账号最多 4096 条；不保存提示词、回答或工具结果。只有可靠的显式会话字段或 `previous_response_id` 链允许复用；裸 `user` 字段及提示词指纹不视为可靠的上游会话标识。这一路径已实测跨两个独立网关进程保持原生会话与上下文；它不能恢复尚未完成的工具通道。

没有可靠会话字段的 Robin 请求，每个新任务使用独立的临时任务标识，不能因为首条提示相同而共用正在执行的原生任务。续接存活工具流只通过网关实际交付的工具调用 ID：[Responses 使用 `call_id` 对应工具结果](https://developers.openai.com/api/docs/guides/function-calling)，其余协议经共用解析层归一。内存索引只保存有限期的哈希归属，不保存工具参数、结果或对话内容；跨调用者、跨凭据、跨 Provider 的旧任务不能被续接，归属歧义仍返回 409。索引已丢失但请求自带完整调用和结果时，建立隔离的新任务，不查找或借用其他调用者的上下文；只有结果而没有调用历史时仍拒绝。普通新消息依靠客户端提交历史，不猜测它属于哪个旧任务。Robin 同一会话下无工具且无工具结果的辅助请求使用独立传输范围，不占用主工具任务；这不是按提示词识别任务意图。

Pi 实际使用的 `session_id` Header 也可作为可靠会话字段；`x-session-affinity` 和 `prompt_cache_key` 仅作为账号亲和提示，不替代 Robin 会话 ID。已有 Cloud Code 身份和账号排序规则保持不变。两个真实 Pi CLI 使用相同提示、未加会话 Header，并发经开发网关调用原生 Argon，均完成各自文件读取，只显示自己的标记且保持各自原生会话；四个 HTTP 请求约 48 秒完成，两次原生任务、一次设备注册，没有串接或重发提示词。

实际 Hermes CLI 在所测自定义 Provider 配置下也没有发送会话 Header、元数据或缓存键。复用临时运行环境并禁用自动安装后，两个相同提示的 Hermes 原生 Argon 主任务约 85 秒完成：工具调用 ID 各不相同、结果回到各自原生会话、最终回复均为任务模式且只显示自己的文件标记，源文件未改变。中间工具帧可以缺少可选的模式元数据，验收以各自最终回复的真实模式和完整归属链为准，不把请求中的模型名当作证明。Hermes 另外发起的后台辅助请求不计入该次原生主任务验收；辅助请求隔离与收尾另有受控上游测试。

Claude Code 的 Auto Mode 辅助分类仍留在请求模型所属 Provider。Argon 的分类任务和主工具任务使用不同原生会话，账号软黏性仍共用；Cloud Code 的原有快速分类模型规则不变。模型返回的工具调用若未通过统一协议层的 Schema 或 `tool_choice` 校验，网关只关闭该条未交付的 Robin 工具任务，保留账号黏性及最近完成的对话游标，不影响其他客户端。

统一身份解析也识别 DSH 实际发送的 `x-deepseek-harness-user-id`、`x-deepseek-harness-session-id`，显式通用客户端字段仍优先；版本号变化不改写已有 DSH 调用者身份，不同会话或本地用户不会仅因首条提示相同而共用任务。凭据和调用者范围的限制仍生效，路由 Header 不注入模型内容。DSH 使用同一会话 ID 发出的 `x-deepseek-harness-compact: 1` 请求使用独立压缩任务；没有声明客户端工具且没有回传工具结果的请求使用独立无工具任务，两者保留父账号黏性。携带工具结果的请求即使省略工具定义仍走主任务；不根据标题、压缩等提示词关键词分类，不改 Cloud Code 调度。辅助任务的协议校验失败只取消该辅助任务。

## 思考内容与响应协议

原生公开思考摘要在客户端明确要求时通过统一协议层返回，不混入回答正文：Anthropic 使用 `thinking` 内容块，Chat Completions 使用 `reasoning_content`，Responses 使用 `reasoning` / `summary_text` 与对应的流式摘要事件。Responses 的 `reasoning.summary` 遵循[官方摘要格式](https://developers.openai.com/api/docs/guides/reasoning#reasoning-summaries)。仅设置 Responses 的思考 effort 不会自动请求摘要，`none` 会禁用摘要输出。

缓冲与流式交付均有回归测试，包含稳定的事件 ID、顺序、去重，以及不覆盖客户端工具的 opaque signature。真实 Responses 流式任务已返回正确答案和完成事件，但该次上游没有提供公开摘要；不能把格式分支的测试说成实际收到了思考文本。响应保留原生模式/路由 ID、模型归属、fallback 与完成状态用于内部核对。

## 额度与健康状态

Robin 使用原生 `GetUsageInfo` 获取 GXU 周额度和 5 小时窗口，独立保存在账号元数据中。看板在 Gemini 分组下展示剩余比例、重置时间及过期快照提示。该响应的 `UserSubscriptionTier.TIER1`（wire value `2`）已由真实、已知为 Google AI Pro 的授权账号实测对应，因此显示为 `Google AI Pro`；其他未实测 tier 继续保持未命名。

- 后台启动时检查一次，此后每 30 分钟刷新；新绑定发现缺失/失效字段时异步补查。
- 成功快照有效期 30 分钟；窗口重置后提前视为过期。
- 查询失败至少等待 5 分钟再尝试；同账号并发查询合并、后台批次逐个查询。
- 模型请求不等待额度查询，也不因额度遥测失败将账号判为异常。
- 模型请求返回的认证错误、限额及临时故障仍由 Robin 独立健康状态与冷却处理。
- 三条通道复用 Antigravity 的周额度压力、5 小时重置权重与平滑加权轮询；健康黏性不读额度或消耗轮询权重。新任务有其他可用账号时避开耗尽快照，只剩耗尽快照时保留最后兜底，不将其标为账号健康异常；实际限流才进入冷却。
- 快照统一为 30 分钟有效期和后台刷新周期，缺失/失效字段或实时额度错误触发异步补刷新，至少间隔 5 分钟。实际限流按上游重试时间冷却，无提示默认 60 秒；瞬态失败为 15 秒。凭据、上游额度接口及工具任务保护仍独立，正在执行的工具任务继续原有通道。

没有经过验证的套餐名称不在看板中编造。`GetUserStatus` 中的实验策略记录不作为产品能力，网关不据此探测、保存或展示思考档位。额度比例也不是 token 用量，不能相互换算。

Robin 尚未提供可解析的原生 token 用量，因此内部 `usage=null`、`usageKnown=false`，不把未知用量计入 token 测量。Chat Completions 的可选 `usage` 缺省不输出；Responses 返回 `usage:null`；Anthropic 必需的数字字段暂保留兼容占位。三个协议都以网关扩展字段 `usage_known:false` 明示未知，不表示“消耗为零”。Chat 的 `stream_options.include_usage` 沿用[官方流式格式](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events#chat.completion.chunk)：中间块为 `usage:null`，最后使用空 `choices` 的用量块；没有真实测量时，最后的用量仍为 `null`，不编造 token 数。

看板 API 通过账号的 `tokenUsageKnown` 和顶层 `tokenUsageMetadata` 明示测量覆盖范围，不改写原有请求、失败或 token 计数。只显示未提供用量的账号时，Token、输入、输出及缓存指标为 `--`，不绘制假的零值曲线、柱状图或占比；账号卡片显示“Token 未提供”。混合账号时明确标注“仅统计已测量部分”，Token 图表从已测量账号的现有细分数据计算，不给未知账号编造零值曲线或百分比。请求次数、失败率与原生额度继续正常显示；真实测量为零仍显示 `0`。计算留在前端，不增加上游查询或重复发送整份统计快照；本次修复前后 CSS 字节校验一致，并已完成五档实际窄屏渲染验收。
