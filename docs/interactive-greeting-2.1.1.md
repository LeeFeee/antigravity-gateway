# 2.1.1 交互模式请求修复

日期：2026-11-17。完整请求、账号对应关系、用户规则、响应及安装日志保存在仓库外受限目录。本文仅记录脱敏证据。

## 为什么 2.1.0 的通过记录没有覆盖此次失败

2.1.0 的真实文件任务验证使用 `claude -p` 和 Hermes `--format stream-json`。这两种启动方式确实产生了完整请求并完成真实工具任务，但它们与直接打开交互终端使用的框架提示不同，不能互相代替验收。

- Claude Code 2.1.322 交互请求已被识别为 `claude-tui-system-template`，但兼容转换只处理 SDK 普通与 compact 模板。交互框架还保留一个开头换行，因此没有进入同一安全段落的转换分支。
- Hermes 的普通交互终端通过其后台发送请求，会额外加入 `agent/prompt_builder.py` 的 `STEER_CHANNEL_NOTE`。stream-json 测试请求没有这段说明。新增段落包含默认客户端身份声明，旧转换遗漏了它。

两台 Hermes 的版本分别为本机 `0.23.1 / 3b4215785882` 与服务器 `0.23.1+4394.gc9b20d7 / c9b20d7bc08`。本次分别捕获它们的交互请求，保留全部 20 / 19 个工具、SOUL 和正常用户上下文；没有用本机结果代替服务器客户端。

## 修复范围

Claude 交互框架经过既有完整前缀指纹识别后，应用与 SDK 相同的安全段落指纹校验和缩写展开。拒绝规则、授权要求、权限合同及用户内容原样保留；不修改客户端审批设置。

Hermes 只转换官方框架区域内 SHA-256 为 `7af6922616db050fd7a240cc80aebee4cefc4d89e32dcacc0c69c54deac26d43` 的完整段落，将 `Hermes delivers` 改为 `The client delivers`。用户消息标记、指示权限、信任边界及历史重放规则全部保留。用户引用、项目内容和改写过的段落不匹配，不予修改。

## Pi 的同期失败

用户原 Pi 会话前两轮均正常结束。第三轮在客户端记录的约 0.37 秒内返回 `account_pool_unavailable`，并非已收到 Google 对该轮内容的拒绝。网关同期记录了 Hermes/Claude 的连续 429 与共享账号池冷却。后续用保留原上下文的 Pi 会话复验，不为此删除历史、降低档位或建立额外续聊路由。

## 边界

上述对照证明这两项精确转换能解决已复现请求，不能据此推断 Google 内部的拒绝机制，也不表示所有 429 都是提示词问题。真实额度、上游限流、账号粘性、轮询、冷却及 Google Gemini API 行为不变。

本次新增覆盖交互模板、不可变转换、用户引用与自定义段落保留的回归测试。完整测试共 1193 项通过，0 失败。安装命令、数据目录、密码/密钥、账号池、配置与端口约定保持不变。
