# Hermes 追加指令导致的 429：真实对照与修复

2026-11-18 收到一份完整 Hermes Chat Completions 请求：`gemini-3.8-flash-high`、流式、21 个客户端工具、10,218 字符系统提示。请求体 SHA-256 为 `82f1bcf7b58bf2123e0940a4bb365465f662d8bff82906c27009aef59ad85f4e`。完整提示、账号和原始上游报文只存于仓库外受限目录。

## 可复现原因

Hermes 的运行环境块以 `<!-- End Hermes runtime environment -->` 结束。该请求在结束标记之后追加了自定义身份和执行规则。旧转换要求整个系统提示必须以该标记结束，因而跳过了运行环境框架标签的转换。

修复根据已确认的 Hermes 日期、模型、提供方和平台元数据定位运行环境块，再以对应关闭标记确定结束位置。只转换标题和关闭标记；环境值、追加指令、工具、消息、权限和模型配置均保留。重复来源标记无法消除歧义时保留原文，不猜测修改用户引用。

Google 没有公开通用 `RESOURCE_EXHAUSTED` 的内部判定规则。这里确认的是该样本的因果对照：同一账号、出口、安装版本和模型，仅转换这两个框架标签，失败就变为成功；恢复旧转换后再次失败。

## 真实验证

测试读取服务器现有账号到进程内存，固定一个账号，通过实际安装的 Gateway HTTP 入口及原生传输访问真实 Google。没有复制账号文件、自动换账号、删除提示、删除工具或替换模型。

| 对照 | Google / 客户端结果 |
| --- | --- |
| 原始完整请求，旧转换 | 两轮均为 Google 429；没有正常完成事件 |
| 同账号、同模型的完整 Hermes 对照请求，穿插在两次失败之间 | 两轮 Google 200，真实工具调用、用量和 `[DONE]` |
| 原始完整请求，仅修复运行环境边界 | `收到`，`stop`、`[DONE]`；26,435 输入 / 2,072 输出 token |
| 恢复旧转换，原始完整请求 | Google 429，再次失败 |
| 再次启用边界修复，原始完整请求 | `收到`，`stop`、`[DONE]`；26,435 输入 / 4,778 输出 token |

上游报文对比确认：工具声明完全相同、模型和 `HIGH` 思考配置完全相同、自定义尾部逐字保留；系统提示的唯一变化是两个框架标签。成功请求分别耗时约 49.5 秒和 184.8 秒，不能由此声称上游延迟已修复。

最初一组诊断程序的模块加载顺序导致候选转换没有生效，抓包核验后已作废，不作为修复前后证据。另一个试验同时修改了浏览器描述，未合入，也不计入上述单变量验收。

## 额度与容量错误的区别

对照账号的 Gemini 周额度和五小时额度均剩余约 98.99%，并能在失败请求之间完成同模型推理，因此这份样本的失败不能归因于账号余额耗尽。

测试期间另有请求真实收到日常入口 `503 UNAVAILABLE / MODEL_CAPACITY_EXHAUSTED`，备用入口随后返回无具体原因的通用 429。旧代码只保留最后错误，掩盖了已知的模型容量不足。修复保留明确的容量证据，对客户端输出 `overloaded_error / model_capacity_exhausted`；具体额度错误、认证错误和成功的备用响应继续按实际结果处理。每个上游失败入口记录状态和结构化原因，不记录提示或凭据。

容量错误映射以本次真实错误体补充回归；不将历史报文回放或单元测试冒充新的实时容量失败验收。通用 429 仍忠实返回，不一概猜测为提示问题、封禁或额度归零。
